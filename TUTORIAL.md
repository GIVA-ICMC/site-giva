# Creating People, Posts, and Publications Pages

## 1. How the site is organized

The site is a plain Hugo site with its own layouts in `layouts/`. The three content types are just three
Hugo sections:

| What you are creating | Where the file goes | Public URL | Template used |
| --- | --- | --- | --- |
| Person | `content/people/<slug>.md` | `/people/<slug>/` | `layouts/people/single.html` |
| News post | `content/post/<bundle>/index.md` | `/post/<bundle>/` | `layouts/post/single.html` |
| Publication | `content/publication/<bundle>/index.md` | `/publication/<bundle>/` | `layouts/publication/single.html` |

`<slug>` and `<bundle>` become part of the URL, so use lowercase letters, numbers, and
hyphens. They are also the identifiers used to link content to people and publications.

The section index pages (`/people/`, `/post/`, `/publication/`) are controlled by
`_index.md` files. Their titles are rendered by the list templates; the people list also
renders any Markdown body placed in `content/people/_index.md`.

### Before you start

```bash
# local preview with live reload
hugo server

# local preview including drafts and future-dated pages
hugo server -D -F

# production build (writes to public/, which is generated and git-ignored)
hugo --gc --minify
```

Do not edit files in `public/`. That directory is generated by Hugo and ignored by Git.

## 2. Creating a person

People are flat Markdown files: one file per person directly in `content/people/`.
The filename is the person's slug. For example:

```text
content/people/jane-doe.md        ->  /people/jane-doe/
```

### 2.1 Minimal person page

```markdown
---
title: "Jane Doe"
first_name: "Jane"
last_name: "Doe"
userGroup: ["Grad Students"]
role: "PhD Candidate"
---

Jane is a PhD candidate working on computer vision and medical imaging.
```

This is enough to make the person appear on `/people/`, grouped under **Grad Students**,
and to create their profile page.

### 2.2 Complete person page

```markdown
---
title: "Jane Doe"
first_name: "Jane"
last_name: "Doe"
userGroup: ["Grad Students"]
role: "PhD Candidate"
organizations:
  - name: "ICMC-USP"
    url: "https://www.icmc.usp.br/"
social:
  - icon: "envelope"
    link: "mailto:jane@example.com"
  - icon: "github"
    link: "https://github.com/janedoe"
  - icon: "google-scholar"
    link: "https://scholar.google.com/citations?user=XXXXXXXXXXXX"
interests:
  - "Computer Vision"
  - "Medical Imaging"
  - "Deep Learning"
education:
  courses:
    - course: "PhD in Computer Science"
      institution: "ICMC-USP"
      year: 2026
    - course: "MSc in Computer Science"
      institution: "ICMC-USP"
      year: 2022
avatar: "/uploads/jane-doe.jpg"
---

Jane Doe is a PhD candidate at ICMC-USP. Her research focuses on computer vision
and medical imaging. She is advised by ... and works on ...
```

### 2.3 Person field reference

| Front matter key | Required | What the code does with it |
| --- | --- | --- |
| `title` | Yes | Full name, shown on cards, profile, and author lists. |
| `first_name` | No | Used for the initial shown when no avatar exists. |
| `last_name` | Strongly recommended | Sort key for every group except Grad Students, which sorts all of its blocks by `title`. Use the surname only. |
| `userGroup` | Yes | Array of group names. Controls which section(s) the person appears in. Must match the exact names listed below. |
| `role` | No | Shown under the name on the card and on the profile. Also controls special ordering inside Grad Students. |
| `organizations` | No | List of `{name, url}` objects, printed on the profile. Links are optional. |
| `social` | No | List of `{icon, link}` objects. Rendered as text links with friendly labels. |
| `interests` | No | List of strings, rendered as an "Interests" list on the profile. |
| `education` | No | Object containing a `courses` list of `{course, institution, year}`. |
| `avatar` | No | Path to an image in `static/` (see below). Without it, an initial is displayed. |
| Markdown body | No | Rendered as the "Biography" section on the profile. |

### 2.4 Groups and ordering

The people list template (`layouts/people/list.html`) recognizes exactly these groups, in
this order:

1. `Professors`
2. `Principal Investigators`
3. `Researchers`
4. `Grad Students`
5. `Undergraduate Students`
6. `Administration`
7. `Visitors`
8. `Alumni`

A group with no members is hidden. A person can belong to more than one group by adding
multiple values:

```yaml
userGroup: ["Professors", "Researchers"]
```

That will show the same person in both sections.

Ordering is not purely alphabetical:

- **Grad Students** are ordered in three blocks: first everyone with
  `role: "PhD Candidate"` (sorted by `title`), then `role: "Master's Student"`
  (sorted by `title`), then everyone else (sorted by `title`). The role strings are
  case-sensitive, so `"PhD candidate"` will not land in the first block.
- **All other groups**, including Researchers and Undergraduate Students, are sorted by
  `last_name`.

The group names above are the source of truth. The README omits `Professors` and
`Undergraduate Students`; both are used throughout the current content and are supported
by the layout.

### 2.5 Avatars

Avatars are not page resources. Put the image in `static/uploads/` and reference it with
an absolute path:

```text
static/uploads/jane-doe.jpg   ->   avatar: "/uploads/jane-doe.jpg"
```

Use a reasonably sized JPEG, PNG, or GIF. If the field is missing or the file cannot be
found, the site shows a placeholder with the first letter of `first_name`.

### 2.6 Social icons

The profile template maps these icon names to labels:

`envelope`, `twitter`, `google-scholar`, `github`, `linkedin`, `orcid`,
`researchgate`, `youtube`, `instagram`, `facebook`, `website`.

Any other value is humanized and used as the label. For email, use the `envelope` icon
and a `mailto:` link:

```yaml
social:
  - icon: "envelope"
    link: "mailto:jane@example.com"
```

The icons are displayed as text links, not graphical icons.

### 2.7 Why the slug matters

Publication pages and post front matter refer to people by **slug**, not by full name.
For example, if the file is `content/people/jane-doe.md`, other content must use:

```yaml
authors:
  - jane-doe
```

The template calls `site.GetPage` on `/people/<value>`. If the page exists, the author
name is linked to the profile. If it does not, the value is printed as plain text. This is
why filenames should be stable: renaming `jane-doe.md` breaks every author link that uses
`jane-doe`.

### 2.9 Verify

1. Run `hugo server`.
2. Open `/people/` and check that the person appears in the intended group.
3. Open `/people/jane-doe/` and check the profile, links, education, and photo.
4. Open a publication that lists `jane-doe` and confirm the author name links back.

## 3. Creating a news post

Posts are page bundles. Create a folder under `content/post/` containing an `index.md`:

```text
content/post/2026-11-05-jane-best-paper/
├── index.md
└── featured.png        # optional
```

The folder name becomes the URL: `/post/2026-11-05-jane-best-paper/`. The date prefix is
only a convention; the date that Hugo uses comes from the `date` front matter field.

### 3.1 Minimal post

```markdown
---
title: "Jane Doe wins Best Paper Award"
date: 2026-11-05
summary: "Jane Doe received the Best Paper Award at the conference."
---

Jane Doe received the Best Paper Award at the conference for her work on ...
```

### 3.2 Complete post

```markdown
---
title: "Jane Doe wins Best Paper Award"
date: 2026-11-05
summary: "Jane Doe received the Best Paper Award at the conference."
tags:
  - award
authors:
  - jane-doe
publications:
  - region-aware-cls-token-augmentation
image:
  filename: "featured.png"
---

Jane Doe received the Best Paper Award at the conference for her work on ...

The work is described in the [related publication](/publication/region-aware-cls-token-augmentation/).
```

### 3.3 Post field reference

| Front matter key | Required | What the code does with it |
| --- | --- | --- |
| `title` | Yes | Post title on the list, article, and homepage card. |
| `date` | Yes | Controls ordering on `/post/` and which posts appear on the homepage. |
| `summary` | No | Plain-text excerpt on `/post/`. Also used on the homepage when there is no image. |
| `description` | No | Fallback excerpt when `summary` is absent; also becomes the meta description. |
| `tags` | No | Displayed on the article page. See the known tag-link issue below. |
| `authors` | No | Present in existing posts, but **the current post templates never display it**. Include it for consistency or future use only. |
| `publications` | No | List of publication slugs. Rendered as "Related publication" links at the bottom of the article. |
| `image.filename` | No | Page resource to show inside the article, after the body. Must match a file in the bundle. |
| `draft` | No | Set `true` to exclude the post from normal builds. |
| Markdown body | Yes | Article content. |

The excerpt on `/post/` is chosen in this order:

1. `summary`
2. `description`
3. the post body, converted to plain text and truncated to 220 characters

`summary` is inserted as plain text, so do not put Markdown or HTML in it.

### 3.4 Images

There are two different image behaviors:

- **Homepage cards** automatically look for a bundle resource whose name starts with
  `featured`, then one starting with `image`. A file named `featured.png` is enough.
  When a card has an image, the summary is hidden and only the date and title are shown
  next to it.
- **The article page** only shows an image when the front matter explicitly names it
  under `image.filename`. The file must be a resource in the same bundle. The image is
  rendered **after** the article body, not below the title.

To get both behaviors with one file, use `featured.png` in the bundle and set:

```yaml
image:
  filename: "featured.png"
```

The `/post/` list itself does not show images.

### 3.5 Related publications

The `publications` list contains publication slugs (the folder names under
`content/publication/`). The template looks each one up with `site.GetPage` and renders a
link. A missing slug is silently skipped.

```yaml
publications:
  - differentiable-lifting-topological-neural-networks
```

This is the recommended way to connect a news post to a paper. You can also link to the
paper manually in the body with `/publication/<slug>/`.


### 3.6 Verify

1. Run `hugo server -D -F`.
2. Open `/post/` and check the new entry at the top (newest date first).
3. Open the article and check the body, image placement, and related publication links.
4. Open `/` and confirm the post appears in the six most recent post cards.

## 4. Creating a publication

Publications are page bundles, like posts:

```text
content/publication/jane-doe-best-paper/
├── index.md
├── featured.png        # optional featured image
└── anything-else       # optional; no other file is used automatically
```

The folder name is the publication slug and becomes the URL:
`/publication/jane-doe-best-paper/`. Use this slug when cross-linking from a post.

### 4.1 Minimal publication

```markdown
---
title: "A Great Paper About Vision"
authors:
  - jane-doe
  - John Smith
date: "2026-11-05T00:00:00Z"
publication_types: ["paper-conference"]
publication: "*Proceedings of the Conference*, 2026"
---

Optional notes about the paper.
```

`John Smith` is not a slug of a people page, so it is displayed as plain text. `jane-doe`
links to the corresponding profile because `content/people/jane-doe.md` exists.

### 4.2 Complete publication

```markdown
---
title: "A Great Paper About Vision"
authors:
  - jane-doe
  - John Smith
  - moacir-antonelli-ponti
date: "2026-11-05T00:00:00Z"
publication_types: ["paper-conference"]
publication: "*Proceedings of the International Conference on Vision*, 2026"
abstract: "We present a method for ... The experiments show ..."
doi: "10.1234/example.2026.001"
url_pdf: "https://example.org/paper.pdf"
url_code: "https://github.com/janedoe/great-paper"
url_dataset: "https://example.org/dataset"
url_poster: "https://example.org/poster.pdf"
url_slides: "https://example.org/slides.pdf"
url_video: "https://example.org/video"
url_source: "https://arxiv.org/abs/1234.56789"
image:
  caption: "Figure 1. Overview of the proposed method."
---

Optional notes, acknowledgements, or a link to a project page.
```

### 4.3 Publication field reference

| Front matter key | Required | What the code does with it |
| --- | --- | --- |
| `title` | Yes | Paper title on the list, article, and related-publication links. |
| `authors` | No | Ordered list. Values matching a people slug are linked; everything else is plain text. |
| `date` | Yes | Used for ordering on `/publication/` (newest first) and the year shown on the article. |
| `publication_types` | No | Array; only the first value is used, as the type badge. |
| `publication` | No | Venue line. Rendered with Markdown, so `*Journal Name*` becomes italics. |
| `abstract` | No | Rendered as plain text in an "Abstract" block on the article. Markdown is not rendered. |
| `doi` | No | Bare DOI. The template creates `https://doi.org/<doi>` and shows a "DOI" link. |
| `url_pdf` | No | Adds a "PDF" link. |
| `url_code` | No | Adds a "Code" link. |
| `url_dataset` | No | Adds a "Data" link. |
| `url_video` | No | Adds a "Video" link (article page only). |
| `url_poster` | No | Adds a "Poster" link (article page only). |
| `url_slides` | No | Adds a "Slides" link (article page only). |
| `url_source` | No | Adds a "Source" link (article page only). |
| `image.caption` | No | Caption shown under the featured image, rendered as Markdown. |
| Markdown body | No | Extra content rendered after the abstract. |

The list page (`/publication/`) shows only PDF, DOI, Code, and Data links. The article
page shows all supported links.

### 4.4 Publication types

Only the first item in `publication_types` is displayed. Hugo's `humanize` function turns
the value into the badge text, so existing values render as:

| Value | Badge |
| --- | --- |
| `article` | Article |
| `article-journal` | Article journal |
| `paper-conference` | Paper conference |
| `chapter` | Chapter |

These are the values currently used in the repository. Nothing validates the value, so a
typo will simply produce an odd badge.

### 4.5 Authors and people links

Author values are matched with `site.GetPage` against `/people/<value>`. This is an exact
path lookup:

```yaml
authors:
  - jane-doe                      # links to /people/jane-doe/
  - Jane Doe                      # plain text, no link
  - jose-da-silva                 # plain text if that page does not exist
```

Use the filename without `.md`, exactly as it appears on disk. Author order is preserved.

### 4.6 Featured image and caption

Put a file whose name starts with `featured` in the publication bundle. The article
template finds it with `.Resources.GetMatch "featured*"` and displays it between the
header and the abstract. The caption comes from `image.caption` and is Markdown-enabled.

Note that the featured image is shown **only** if a matching `featured*` resource exists;
the `image` front matter alone does not create an image. Conversely, the caption is only
rendered inside the image block.

Other files in the bundle (for example `cite.bib`) are not linked or rendered by the
current templates. If you want a downloadable BibTeX file, put it under `static/` or add
a link to it manually; simply placing it in the bundle does nothing.

### 4.7 The citations chart

`/publication/` includes a citation chart when `data/scholar_citations.json` exists. The
chart is rendered by `assets/js/citations-chart.js` using Plotly. The JSON shape is:

```json
{
  "years": [2024, 2025, 2026],
  "series": [
    {
      "name": "Jane Doe",
      "values": [10, 25, 30]
    }
  ]
}
```

Only `years` and each series' `values` are used; the template sums all series per year
and plots one "All faculty" line. Other keys such as `source`, `retrieved`, `id`, and
`color` are ignored by the current JavaScript. Update this file manually when the chart
should change. The script `forms_responses/scholar_citations.py` fetches Scholar data but
writes a CSV/PNG, not this JSON file.

### 4.8 Verify

1. Run `hugo server`.
2. Open `/publication/` and check the new entry near the top and its type badge.
3. Check that authors with people pages are linked and external authors are plain text.
4. Open the publication page and check the abstract, venue, featured image, and links.
5. Open the related post and confirm the "Related publication" link works.

### 4.9 Bulk import

`forms_responses/import_publications.py` builds publication pages from faculty publication
rows, student paper lists, and DOI/URL columns. It fetches metadata from Crossref and
arXiv and accepts `--overwrite`. Use it for bulk imports, then review the generated
front matter manually.

## 5. End-to-end example

Suppose Jane Doe joins the group and publishes a paper.

1. Add `content/people/jane-doe.md` with `userGroup: ["Grad Students"]`,
   `role: "PhD Candidate"`, and `avatar: "/uploads/jane-doe.jpg"`.
2. Add her photo at `static/uploads/jane-doe.jpg`.
3. Add the paper bundle:
   `content/publication/jane-doe-best-paper/index.md`, using `jane-doe` in `authors`.
4. Add the news bundle:
   `content/post/2026-11-05-jane-best-paper/index.md`, with
   `publications: [jane-doe-best-paper]` and optionally
   `image.filename: "featured.png"`.
5. Run `hugo server -D -F` and verify `/people/jane-doe/`,
   `/publication/jane-doe-best-paper/`, `/post/2026-11-05-jane-best-paper/`, and `/`.
6. Remove `draft: true` or make sure the date is not in the future before publishing.

## 6. Pre-publish checklist

- [ ] File is in the correct section and the slug is lowercase/hyphenated.
- [ ] `title` and `date` are set.
- [ ] Person: `userGroup` uses an exact supported group; `last_name` is the surname.
- [ ] Person: avatar is in `static/uploads/` and the path is correct.
- [ ] Publication: authors use people slugs where links are wanted.
- [ ] Publication: `doi` is a bare DOI, not a full URL.
- [ ] Post: `summary` is plain text and useful in the list.
- [ ] Post: related publication slugs exist.
- [ ] Post: `image.filename` matches a bundle resource if the article should show an image.
- [ ] `draft` is not left as `true`.
- [ ] Date is not in the future unless the post is intentionally scheduled.
- [ ] `hugo server -D -F` shows the page where expected.
- [ ] `hugo --gc --minify` finishes without errors.
